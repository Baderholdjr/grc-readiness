# {{title}}

## Purpose

This procedure sets how {{client}} publishes public information about its cloud service offering, shares FedRAMP certification data with agencies and FedRAMP through a trust center, reports availability, and keeps historical certification data.

These rules apply to Class B and C. For Class A, CDS-CSO-PUB, CDS-CSO-UTC and CDS-UTC-AAD are also mandatory (FRC-CLA-MFR), and CDS-CSO-AVR applies as a SHOULD (see "Availability reporting").

## Public information

{{client}} must publicly share up-to-date information about the offering in both human-readable and JSON formats (CDS-CSO-PUB). It includes at least the following, where available and applicable:

- FedRAMP ID;
- service model and deployment model;
- business category;
- UEI number;
- sales contact and security contact information;
- product website link;
- link to the product logo: a valid, properly named image link that displays in a browser without processing (transparent PNG preferred);
- overall service description;
- detailed list of services and their security categories (CDS-CSO-SVC);
- link to the secure configuration guidance (see DOC-FR-SCG);
- overview of the documentation {{client}} supplies for the offering;
- link to the trust center landing page, with instructions for accessing information in it;
- next Ongoing Certification Report date (see DOC-FR-CONMON);
- current FedRAMP Recognized independent assessment service.

## Trust center

{{client}} must use a FedRAMP-compatible trust center to store and share certification data with all necessary parties (CDS-CSO-UTC). The trust center is [[TODO: trust center product or service and URL]].

The trust center:

- must share certification data with all necessary parties without interruption, meaning no manual approval each time and no complicated process; on-demand just-in-time access provisioning is preferred (CDS-TRC-USH);
- must provide documented programmatic access to all certification data, including the human-readable materials (CDS-TRC-PAC); documentation is at [[TODO: URL of API documentation]];
- should let parties view and download certification data in both human-readable and machine-readable formats (CDS-TRC-HMR);
- should include self-service features so necessary parties can provision and manage access for their own users and services (CDS-TRC-SSM).

If {{client}} does not follow CDS-TRC-HMR or CDS-TRC-SSM, the reason and the resulting risk to customers are recorded in the security decision record (see DOC-FR-PACKAGE) and accepted by a senior official.

### Responsible sharing

{{client}} must provide enough information in certification data to support agency authorization decisions, but should not include sensitive information that would likely let a threat actor gain unauthorized access, cause harm, disrupt operations or otherwise adversely affect the offering (CDS-CSO-RIS). This does not permit leaving out accurate risk information; it means abstracting specifics that would likely lead to compromise. {{client}} assumes certification data may one day leak.

Before publishing, the author checks that the material contains no:

- passwords, API keys or other access credentials;
- excessive detail about methods that exposes weaknesses;
- personal information about employees, such as names and direct phone numbers tied to roles.
